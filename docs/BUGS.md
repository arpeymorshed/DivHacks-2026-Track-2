## Fixed

- [x] 2026-09-27: On `aartee.tech`, every route that loads `xrpl` returned a bare HTML 500 before its own code ran: `/api/state`, `/api/clock`, `/api/topup`, `/api/tick`, `/api/tenants`, `/api/attacks/*` (Reviewer, top priority; also covers the older `/api/state` entry). Repro: Vercel Runtime Logs showed `ERR_REQUIRE_ESM: require() of ES Module .../@xrplf/isomorphic/node_modules/@noble/hashes/utils.js`. Locally, `node --no-experimental-require-module -e 'require("xrpl")'` gives the same error. (fixed: `xrpl` 4.6.0's CommonJS dependencies pull in two ES-module-only packages, `@noble/hashes` 2.x via `@xrplf/isomorphic` 1.0.2 and `@scure/base` 2.x via `ripple-address-codec` 5.0.1. Node 24 locally can `require()` those, but Vercel's function runtime can't, so every route that loaded xrpl crashed on load. `package.json` `overrides` pins them to the CommonJS `@noble/hashes` 1.8.0 and `@scure/base` 1.2.6 that the rest of xrpl already uses. The functions they call (`concatBytes`, `utf8ToBytes`, `base58xrp`) exist in both versions. Verified with require(esm) disabled: xrpl wallet, sign, verify and decode work; guardian tests pass 18/18; `next start` serves `/api/state` with live ledger balances and `/api/clock` as JSON; `/api/topup` loads. Earlier the same day, PR #28 also made `/api/state` and `/api/clock` not depend on xrpl at load time (lazy import in `stateService`, Buffer hex helpers in `lib/xrpl/memos.ts`). That alone didn't fix Vercel.)
- [x] 2026-09-27: Late-fee split could exceed the unit's legal cap when roommates pay in sequence (found by merge-check review on `late-fee-fix`). Steps: day 20, both 4B roommates late → Kashish pays with a $25 fee → Abhimanyu pays later and was charged $50 (unit total $75 > $50 cap); the Guardian checks per wallet so it would accept it. Cause: "late roommates" only counted currently-unpaid tenants. Fix (Builder, same branch): shared `lateFeeOpts` counts roommates who are unpaid or paid with a fee, and caps each fee by what's left of the unit cap; rent day and /api/state both use it. Test: "paying in sequence never exceeds the unit's legal cap".
- [x] 2026-09-27: `/demo` toasts unreadable in dark mode (light text on white). Fixed in Tailwind restyle (`cursor/tailwind-ui-5063`): toasts use `bg-surface` + theme tokens so dark mode keeps readable ink. Owner: Builder.
- [x] 2026-09-26: Every API route that talks to XRPL hangs under Next.js (`/api/demo/reset`, `/api/rent-day`, `/api/topup`, `/api/attacks`, `/api/tenants`). Steps: `npm run dev`, `POST /api/demo/reset` → no response; dev log shows `TypeError: bufferUtil.mask is not a function` (ws/lib/buffer-util.js) and then an xrpl `server_info` timeout. Cause: webpack bundles `ws` (used by xrpl) and breaks its optional native helpers. The same code works under plain Node/tsx. Would also break on Vercel. Fix (Builder, branch `fix/xrpl-server-bundling`): `experimental.serverComponentsExternalPackages: ["xrpl", "ws"]` in next.config.mjs. Found by the end-to-end route test of PR #16. **Fixed on `fix/xrpl-server-bundling`; verified: full route flow passes (rent day real payments, already-paid refusal, day-8 top-up + late fee, attacks, reset → pays again).** **Merged in #18.**
